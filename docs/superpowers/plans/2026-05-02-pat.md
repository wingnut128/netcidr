# Personal Access Tokens — Implementation Plan

**Spec:** `docs/superpowers/specs/2026-05-02-personal-access-tokens-design.md`
**Date:** 2026-05-02
**Branch:** `feat/personal-access-tokens` (worktree `.worktrees/pat`)
**Target version:** v0.25.0

## Strategy

Subagent-driven, six phases, two-stage review per phase (implementer → controller). Same shape that worked for multi-tenant isolation (v0.24.0). Phases are dependency-ordered; each one ends in a green `cargo clippy --all-targets --all-features -- -D warnings` and `cargo test --all-features`.

```
Phase 1: Storage layer       (model + migration + IpamStore methods + backend tests)
Phase 2: Hashing + minting   (token gen, pepper handling, mint/verify pure functions)
Phase 3: Auth middleware     (verify_pat path, prefix routing, allowlist re-check)
Phase 4: REST endpoints      (/me/tokens CRUD, OIDC-only guard)
Phase 5: Audit + CLI         (audit columns, netcidr token … subcommands)
Phase 6: Dashboard + release (React page, version bump, CHANGELOG, docs)
```

Each phase has explicit acceptance criteria. **Phase 5 ships a usable feature** (REST + CLI both work end-to-end); Phase 6 is polish + release.

### Task 1.3 — `IpamStore` trait methods

Add to `src/ipam/store.rs`:

```rust
async fn pat_create(&self, input: &CreatePersonalAccessToken) -> Result<PersonalAccessToken>;
async fn pat_get_by_hash(&self, token_hash: &[u8]) -> Result<Option<PersonalAccessToken>>;
async fn pat_list_for_owner(&self, tenant_id: &str, owner_sub: &str) -> Result<Vec<PersonalAccessToken>>;
async fn pat_revoke(&self, tenant_id: &str, owner_sub: &str, id: &str) -> Result<PersonalAccessToken>;
async fn pat_touch_last_used(&self, id: &str, now: &str) -> Result<()>;
async fn pat_reap_expired(&self, before_rfc3339: &str) -> Result<u64>;
```

Notes:
- `pat_get_by_hash` filters `revoked_at IS NULL AND expires_at > $now` in SQL — single predicate.
- `pat_list_for_owner` and `pat_revoke` take both `tenant_id` and `owner_sub` so a stolen tenant_id alone can't enumerate or revoke another user's tokens.
- `pat_touch_last_used` is unscoped because the verifier already proved possession.

**Acceptance:** Trait compiles. Both backends implement it; `cargo check --all-features` passes.

## Phase 2 — Hashing + minting (pure functions, no I/O)

### Task 2.1 — `src/pat.rs` module

Create a new module with these pure functions:

```rust
pub struct PatPepper(Box<[u8]>);
impl PatPepper {
    pub fn from_env() -> Result<Self>;       // reads NETCIDR_PAT_PEPPER, b64url-decodes
    pub fn from_bytes(b: &[u8]) -> Result<Self>;  // for tests; rejects < 16 bytes
}

pub struct MintedToken {
    pub plaintext: String,            // "ncdr_pat_xxx..."
    pub prefix: String,               // first 12 chars
    pub hash: [u8; 32],
}
pub fn mint(pepper: &PatPepper) -> MintedToken;

pub fn hash_for_lookup(plaintext: &str, pepper: &PatPepper) -> Option<[u8; 32]>;
//   None if shape-check fails. Constant work otherwise (regex + sha256).

pub static PAT_SHAPE: Lazy<Regex>;    // ^ncdr_pat_[A-Za-z0-9_-]{43}$
```

- [ ] Use `rand::rngs::OsRng` for the 32 random bytes.
- [ ] `sha2::Sha256` for hashing; feed `secret.as_bytes()` then `pepper.0`.
- [ ] Encode random bytes as `base64::engine::general_purpose::URL_SAFE_NO_PAD`.

### Task 2.2 — Pat module tests

- [ ] `mint` produces tokens that pass `PAT_SHAPE`.
- [ ] `hash_for_lookup(mint(pepper).plaintext, pepper) == Some(mint.hash)`.
- [ ] Wrong pepper → different hash.
- [ ] Bad shape → `None`, no panic.
- [ ] Different mints with same pepper produce distinct hashes (probabilistic — assert 1000 mints have 1000 distinct hashes).
- [ ] `PatPepper::from_bytes(b"")` is an error.

**Acceptance:** `cargo test --all-features pat::` green; clippy clean.

## Phase 3 — Auth middleware

### Task 3.1 — `verify_pat` plumbing

- [ ] In `src/auth.rs`, add a `verify_pat` async function that takes the store, pepper, plaintext token, and current allowlist. Returns a `Principal` with `auth_method = AuthMethod::Pat` and `pat_id` set, or generic auth error.
- [ ] Extend the `AuthMode` / `Principal` types to carry `auth_method` and `pat_id`. Bearer-mode uses `AuthMethod::Bearer`; OIDC uses `AuthMethod::Oidc`.
- [ ] Update `require_auth` middleware to dispatch by header prefix:
  - `Bearer ncdr_pat_…` → `verify_pat`
  - `Bearer <static-bearer>` → existing bearer check (when bearer mode active)
  - `Bearer <jwt>` → existing OIDC check

### Task 3.2 — Audit context wiring

- [ ] Extend `AuditContext` (`src/audit_context.rs`) with `auth_method: Option<String>` and `pat_id: Option<String>`.
- [ ] Middleware populates these alongside the existing `caller_sub` / `caller_email`.
- [ ] `IpamOps` reads them via `audit_context::current()` when constructing `AuditEntry` (already does this for caller fields — additive change).

### Task 3.3 — `last_used_at` async update

- [ ] After a successful PAT auth, spawn a detached `tokio::spawn` that calls `store.pat_touch_last_used(id, now)`. Log errors at WARN level. Never block the request path.

### Task 3.4 — Pepper bootstrap check

- [ ] On `serve` startup with OIDC mode active, require `NETCIDR_PAT_PEPPER`. Refuse to start if absent and OIDC is on, with a clear error message pointing at the env var. Bearer-only mode and CLI-only invocations don't need a pepper.

### Task 3.5 — Middleware tests

- [ ] Valid PAT header → request reaches handler with correct tenant.
- [ ] Expired PAT (insert a row with `expires_at` in the past) → 401.
- [ ] Revoked PAT → 401.
- [ ] Shape-invalid `Bearer ncdr_pat_xxx` (too short) → 401, no DB query (assert via spy/instrumented store).
- [ ] OIDC token still works alongside PATs.
- [ ] PAT for an email no longer in the allowlist → 401.

**Acceptance:** All middleware tests pass; existing OIDC tests still pass.

## Phase 4 — REST endpoints

### Task 4.1 — `/me/tokens` router

New file `src/me_api.rs` (or extend `src/api.rs` — implementer's call, document in self-review):

- [ ] `POST /me/tokens` body `{ name: String, expires_in_days: Option<u32> }`. Validate `name` (length 1–64, no control chars per `validation::clean_text`), `expires_in_days` ≤ 365, default 90. Mint, persist, return `{ id, name, prefix, token, expires_at, created_at }`.
- [ ] `GET /me/tokens`: `pat_list_for_owner` filtered to the authed caller. Map to `PersonalAccessTokenSummary` (no hash, no plaintext).
- [ ] `DELETE /me/tokens/{id}`: `pat_revoke(tenant, owner_sub, id)`. 204 on success. 404 if the row isn't the caller's (per spec — never reveal existence).
- [ ] All three handlers gated by middleware that rejects when `auth_method != Oidc` (PATs can't mint PATs).

### Task 4.2 — Mount the router

- [ ] In `src/api.rs::create_router`, nest `/me` under the OIDC-required auth layer, separate from `/ipam`. `/me/tokens` requires OIDC; `/ipam/*` accepts OIDC, PAT, or bearer.

### Task 4.3 — Endpoint tests

- [ ] `tests/pat_api_tests.rs`: mint via OIDC session, list, revoke, re-list (sees `revoked_at`).
- [ ] PAT trying to `POST /me/tokens` → 403.

- [ ] `expires_in_days = 0` or `> 365` → 400 with validation error.

## Risk register

| Risk | Mitigation |
|---|---|
| `NETCIDR_PAT_PEPPER` rotation lockout | Doc the value as a one-time-set secret; rotation = full re-mint (deferred). |
| `last_used_at` write amplification | Async fire-and-forget; if metrics show pressure, gate to "only write if >5min stale" in a follow-up. |
| Forgotten plaintext at mint time | Plaintext is shown exactly once in dashboard with explicit copy step + warning. CLI prints it once to stdout. |
| Privilege escalation via PAT-mints-PAT | `/me/tokens/*` middleware rejects `auth_method != Oidc`. Tested. |
| Token leak in URLs / logs | Verifier accepts only `Authorization` header; no `?token=` querystring path. Logs scrub the header (existing tracing layer). |

## Out of scope (won't ship in this PR)

- Per-token scopes
- Pepper rotation tooling
- Service-account / org-shared tokens
- Token-usage analytics dashboards

Each is its own future spec.
